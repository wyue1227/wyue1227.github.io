经用户明确要求，通过已连接的Supabase只读SQL，在同一查询中导出指定本人profile的300条饮食记录及65条日期记录。饮食条目范围2026-08-10至2026-10-21，3个月份；没有访问R2或读取图片。

原始导出保存在被Git忽略的`.secrets/connector-diet.json`（目录700、文件600）。`node scripts/prepare-real-preview.mjs`会使用独立随机本地口令构建`.preview/real`；口令保存在`.secrets/local-preview-passphrase.txt`（600），不输出到聊天或命令行。

已用浏览器同一WebCrypto解密函数逐月回读，并与规范化源记录逐字段比较一致（300条、65日期）。本地仅通过127.0.0.1:8137提供加密快照，未公开发布。旧的公开虚构口令不适用于真实快照。

这次是连接器导入，不是无人值守数据库认证。云端午夜任务仍需配置本仓库Secrets和跨仓库调用；不要把本地已取得数据当成云端更新已接通。

## 本仓库配置

| 名称                  | 类型             | 说明                                                                                                                            |
| --------------------- | ---------------- | ------------------------------------------------------------------------------------------------------------------------------- |
| DIET_SUPABASE_URL     | Actions Variable | 目标Supabase项目HTTPS根地址，脚本限定supabase.co域名                                                                            |
| DIET_PROFILE_ID       | Actions Secret   | 明确要分享的本人profile UUID；不由浏览器选择                                                                                    |
| DIET_SUPABASE_KEY     | Actions Secret   | 可读取目标表的服务器凭据；现有server secret不会自动复制到本仓库。该密钥可能权限较大，脚本只做GET/HEAD，但不应将它误称为只读密钥 |

API权限不通过放开anon/RLS解决。本任务不改表、RLS或其他应用的认证。若改用受限数据库角色，应另行设计和验证权限，不在此脚本里偷偷创建。

## 首次全量

配置完后，在本仓库Actions选择“Verify and publish private diet viewer” → Run workflow → main → publish=true、initialize=true。成功才上传新artifact；失败保留当前线上站点。

首先核对导出回执的条数、天数、月份数和时间，再核验解密后的首尾日期、历史月份及当天热量。日志只报计数，不打印记录内容、凭据或口令。发布完成不等于国内手机已验收。

导出同时读取日记录状态与原始汇总，区分完整/部分。若实际表结构已改，脚本会失败而非猜测字段。源分页前后检查条数，但REST分页不是数据库事务快照，无法完全排除期间发生的等条数内容修改；需要严格时点一致性时再设计快照API。此处每日全量核对会重新收敛，不能宣称强事务一致。

## 日常增量发布

每日调用pages.yml，参数：

```json
{ "ref": "main", "inputs": { "publish": true, "initialize": false } }
```

旧数据从 `https://wyue1227.github.io/data/` 读密文，在CI内存中解密比较。每次读取全部源记录，但只有变化月份重加密，其他月份保持原文件名。加密索引总会更新，以标注成功更新时刻。空结果、缺页、重复ID、旧快照缺失/无法解密会阻止发布；不要把错误当成首次初始化自动绕过。

旧月份文件只在当前快照仍引用时进入新artifact。文件名以密文哈希命名，不在URL写食品或日期。密文数量、大小、发布时间仍是可观察元数据；本方案不隐藏这些信息。

## 隐私与恢复

- 不向仓库提交原始导出，不把实际口令写命令行；本地通过可信环境变量/隐藏输入设置，CI从Secret注入。
- 输出目录仅允许`.preview/`，构建回执也留在忽略目录。重复本地构建会将旧构建重命名为`.previous-时间戳`以便恢复，没有删除原始记录。
- 旧单词卡的Service Worker改为退役脚本，只清理gojuon-shell缓存，保留IndexedDB。页面不启用新的离线数据缓存；普通浏览器内存不是不可取证的保险箱。
- 锁定清除页面和内存引用中的明文，不保存口令。无法承诺JavaScript运行时立即擦除所有内存副本。
- 错误口令、损坏密文都无法解密；浏览器较旧不支持WebCrypto时显示说明。微信内置浏览器要实测。
- 失败时查看Actions运行；根本没触发需要独立的超时告警，尚未配置。不把工作流邮件当成未触发监控。
- Pages只能发布密文，不能借noindex或隐藏链接代替加密。更换口令必须initialize=true且全部重新加密；旧接收者已下载内容不能撤回。
