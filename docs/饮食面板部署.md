# 饮食面板：展示与导入分离

## 最终职责

- `wyue1227/GithubAction`：读取 Supabase、字段过滤、分页核对、按月增量加密，再只更新展示仓库的 `site/data/`。
- `wyue1227/wyue1227.github.io`：保存页面和密文、验证静态资源、自动部署 GitHub Pages。浏览器输入口令后本地解密展示。
- 本仓库不需要 Supabase 凭据、profile 配置、分享口令 Secret 或跨仓库令牌。如果已按旧说明添加，不再使用，可在确认后自行移除。

## Pages 发布

main 的代码提交或数据提交均自动触发 `.github/workflows/pages.yml`，通过测试后上传且只上传 `site/`。PR不部署；手动部署不需要参数。

验证失败保留线上旧版。数据尚未导入时，新页面显示入口和虚构示例，不能称为真实数据上线。

## 导入配置

所有配置放在 GithubAction 仓库，具体步骤见其 `docs/diet-pages.md`。跨仓库提交必须使用针对本仓库 Contents:write 的专用 fine-grained PAT / 合适的 GitHub App token；普通 GithubAction 的 GITHUB_TOKEN 不能替代。令牌存为 GithubAction 的 `PAGES_IMPORT_TOKEN`，不在本仓库配置。

加密格式保持 `diet-vault-v1`，PBKDF2-SHA256 600000 次、16 字节盐、AES-256-GCM 12 字节 IV，每个文件独立随机参数。数据目录只接收密文；未变月份复用，删除与历史修改由上游全量核对覆盖。

首次导入在 GithubAction 选择 `diet-pages.yml`，initialize=true；先 dry_run=true 验证，再 dry_run=false 导入。后续 initialize=false。不能把导入提交成功当成 Pages 部署成功，必须继续检查本仓库运行和线上结果。

## 定时与当前边界

新导入任务由现有 Cloudflare 后台调度器调用 GithubAction 的工作流，而不是让 Pages 访问数据库。浏览者不需要访问 Worker。日本凌晨00:00对应UTC15:00。

本次先拆分代码和准备导入工作流，未替换旧 Notion 的午夜映射，也未改签到。跨仓库令牌与分享口令未验证前不打开新定时导入，避免每天重复失败；定时器切换应在首次真实导入、Pages部署和解密验证通过后完成。

真实明文、口令不入库。site/data的历史密文会留在Git历史；换口令不能撤回旧版。没有验证国内手机网络、微信浏览器或“根本没触发”告警。
