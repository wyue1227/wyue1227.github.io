# 本地开发与部署说明

## 一、本地预览

本站是纯静态网站，**没有构建步骤、没有 npm 依赖**。

```bash
cd /Users/wangyue/code/wyue1227.github.io/site
python3 -m http.server 8137
# 浏览器打开 http://127.0.0.1:8137/
```

必须用 `http://` 而不是双击打开 `index.html`，否则 Service Worker（离线缓存）无法注册。
练习功能本身在 `file://` 下也能用。

手机预览（同一 Wi-Fi）：

```bash
cd site && python3 -m http.server 8137 --bind 0.0.0.0
# 手机浏览器访问 http://<电脑局域网IP>:8137/
```

## 二、目录约定

- `site/` 是**唯一会被发布**的目录。仓库根目录的其它内容（`.git`、`docs/`、`README.md`）都不会上线。
- 新增页面 / 样式 / 脚本时，记得同步更新 `site/sw.js` 里的 `PRECACHE` 清单，否则离线时取不到新文件。
- 修改了已缓存的文件后，需要把 `site/sw.js` 里的 `CACHE_VERSION` 递增（`v1` → `v2`），
  这样旧缓存会被清掉、新资源才会生效。**这一步只影响 Cache Storage，不会动 IndexedDB 里的练习记录。**

## 三、部署到 GitHub Pages

工作流文件：`.github/workflows/pages.yml`

流程：`push 到 main` → checkout → `configure-pages` → 上传 `site/` → `deploy-pages`。

特点：

- 使用 GitHub 官方 Pages 部署方式，权限来自内置 `GITHUB_TOKEN`（`permissions: pages: write` + `id-token: write`）。
- 已移除旧流程里的 `secrets.TOKEN`，**不需要也不应该再新建个人访问令牌**。
- 旧流程（Hexo 构建后推送到 `gh-pages` 分支）已停用。
- 只上传 `site/`，因此不会发布 `.git`、备份目录、`node_modules` 或旧博客文章。
- 远程 `gh-pages` 分支**没有删除**，随时可以回退。

### 首次上线需要做的一步

仓库 **Settings → Pages → Build and deployment → Source** 必须选择 **GitHub Actions**。
如果当前仍是「Deploy from a branch」（例如指向 `gh-pages`），新工作流跑完也不会生效，
需要手动切换一次；切换后 `gh-pages` 分支上的旧内容不再对外提供服务（但分支本身保留）。

## 五、数据结构

IndexedDB 数据库 `gojuon-db`（版本 1），三个对象仓库：

| 仓库 | 主键 | 内容 |
| --- | --- | --- |
| `kanaStats` | `id`（如 `hira:あ`） | `attempts` / `correct` / `wrong` / `lastResult` / `lastAt` / `firstAt` |
| `daily` | `date`（`YYYY-MM-DD`） | `total` / `correct` / `rounds` / `updatedAt` |
| `settings` | `key` | `kanaFont` / `speech` / `lastSetup` |

### 导出文件格式

```json
{
  "app": "gojuon-trainer",
  "version": 1,
  "exportedAt": "2026-10-16T13:40:00.000Z",
  "counts": { "kanaStats": 46, "practicedKana": 12, "daily": 3 },
  "data": { "kanaStats": [], "daily": [], "settings": [] }
}
```

导入时会依次校验：JSON 可解析 → `app` 标识 → `version` 不高于当前支持版本 →
`data` 三个数组存在 → 每条记录字段类型与数值关系合法（`correct <= attempts`、`correct <= total`、
日期格式）。任一条不通过就整体拒绝，**不写库**。

校验通过后展示预览（导出时间、版本、假名数、每日记录天数、答题总数、正确率），
用户确认才覆盖。写入在单个 IndexedDB 事务中完成，失败会自动回滚到导入前的数据。

## 六、状态口径

| 状态 | 判定 | 界面显示 |
| --- | --- | --- |
| 未练习 | `attempts === 0` 或没有记录 | 徽章「未练习」，正确率显示「—」 |
| 练习中 | `attempts > 0` 且正确率 < 80% 且最近一次答对 | 徽章「练习中」 |
| 已掌握 | `attempts > 0` 且正确率 ≥ 80% 且最近一次答对 | 徽章「已掌握」 |
| 待复习 | `attempts > 0` 且 `lastResult === 'wrong'` | 徽章「待复习」，进入错题本 |

「未练习」永远不会显示成 0% 正确率。
